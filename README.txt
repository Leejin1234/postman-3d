小邮差 · 骑电动车送信的 3D 网页小游戏
=====================================

【手机上体验（同一 WiFi）】
 1. 解压本包到电脑任意目录
 2. 用「管理员」PowerShell 进入该目录，执行：  .\serve.ps1 -Lan
 3. 终端会打印类似 http://192.168.1.23:8130/ 的地址
 4. 手机浏览器打开该地址，点「开始送信」
 5. 可用浏览器菜单「添加到主屏幕」，之后像 App 一样全屏启动

【电脑上体验】
 .\serve.ps1        然后浏览器打开 http://localhost:8130/

【放到静态服务器 / 静态托管】
 把本目录所有文件原样上传即可（纯静态，无后端）。
 必须通过 http(s) 打开；双击 index.html 用 file:// 协议无法加载模型。

【操作】
 骑车时
   手机：摇杆转向，右下「油门 / 刹车」
   电脑：W/S 油门刹车，A/D 转向，空格手刹
 点右侧「下车」按钮（电脑按 F）可下车步行，走到车旁再点「上车」
 步行时
   手机：摇杆拖动 = 走（方向按镜头判断），按住「油门」= 跑，点「刹车」= 跳
   电脑：WASD 走，Shift 跑，空格跳
 玩法：去红色邮箱取信 → 再到绿色光柱处送达 → 得金币与经验升级
       骑车和步行都能完成取信/送达

【调试参数】
 网址后加 ?debug    显示 draw call / 三角数 / FPS / 地平线剔除统计
 网址后加 ?insp     固定侧视角，检查骑坐姿势
 网址后加 ?top=90   正上方俯视 90 米，核对出生点和车流是不是真在马路上
 网址后加 ?auto     自动给油 / 自动前进
 网址后加 ?foot     启动后直接下车
 网址后加 ?footest  跑一遍走/跑/跳数值自测
 网址后加 ?selftest 随机换 6 个出生点各跑 20 秒，看行驶距离与撞击次数
 网址后加 ?noline   关闭几何描边（描边会让提交数翻倍，手机卡就加这个）
 网址后加 ?lw=2     描边线宽倍率，默认 1
 网址后加 ?noink    关闭贴图墨线（窗框 / 面板缝那种内部结构线）
 网址后加 ?noshadow 关闭阴影
 网址后加 ?pc/?mob  强制按桌面档 / 手机档跑（两档画质差别大，排查画面问题必用）
 网址后加 ?mat      地表按材质刷纯色（路面红、草地绿…），天空藏起来背景刷洋红：
                    地上真有洞会露出洋红，黑斑是路面的话会变红
 网址后加 ?fx       循环播放取信/送达动效（测试用）

【画面风格】
 天空是一颗半径 560 米的反面球，贴 assets/sky-real.png（2:1 全景图，等距柱面）。
 球每帧对齐到玩家脚下的「上」方向，所以跑到星球哪一面云海都压在地平线上。
 从球内侧看贴图左右是镜像的（repeat.x=-1 翻回来）；纵向要拉伸 2.2 倍：
 原图是「站在云海之上」的构图，蓝天只占上面 45%，直铺的话 52° 视角从地面往前看
 满屏都是那片白云海、蓝天全在头顶看不见的地方。拉伸后云海压在地平线上方 4°、
 抬头 41° 就到最蓝那层，超出范围用 ClampToEdge 补边。
 赛璐璐动画风：硬边三段明暗（NearestFilter 分色带）+ 反向壳描边。
 描边前会把低多边形的分面法线按顶点位置焊接平均一次（aHull 属性），
 否则沿法线挤出的壳会在每个棱角处裂开露缝。
 星球城市的贴图是「一格一个纯色」的调色板图集，必须用 NearestFilter 采样，
 也不能再叠 Sobel 墨线，否则相邻色格会互相糊到一起。
 没有贴图的路面材质（City_Road / City_Grass 之类）颜色只存在 material.color 里，
 转卡通材质时要原样保留，刷成白色会让整个地面变成一片惨白。
 但 City_Road 的原色 #131417 亮度只有 7%，赛璐璐再压对比就成了死黑，
 贴着饱和的绿草看起来像地上镂空破洞，所以在 CITY_TINT 里抬成沥青灰 #474c54。
 地表（Planet 球壳 + Roads 路面）改双面渲染，而且不投影，两件事各有原因：
 Roads 那层有一半三角形绕序朝内（法线也朝内，模型自带的毛病，见 probe-winding.html：
 City_Road 51.9% / City_RoadLine 50.3% / City_Sidewalk 50.5% 朝内），单面渲染会把
 它们整片背面剔除，路面就一条条露出下面 2 米处的草地，看着像地上镂空破洞；
 不投影是因为球壳一个面 29 米宽、阴影图一像素 0.15 米，自投影只会糊出一片片脏斑，
 shadow.normalBias 也要跟着尺度 S 一起放大。
 顺带说明：球壳和路面层高差恒定 2 米（路面在上，路缘裙边往下扎穿球壳封缝），
 所以这两层不会互相穿插——见 probe-zfight.html 的实测。

【星球世界】
 城市贴在一个半径约 600 米（周长 3.8 公里）的球面上，电动车和角色都能一直
 开到星球背面。位置和朝向合并成一个四元数 frame：
   up = frame·(0,1,0) 朝天，fwd = frame·(0,0,1) 朝前，right = frame·(1,0,0)
   世界坐标 = 球心 + up × (地表半径 + 离地高度)
   前进 d 米 = 绕 right 轴转 d/R（沿大圆走）；转向 = 绕本地 up 轴转
 位置和朝向共用一个量，永远自洽，也不会像「经纬度 + 航向角」那样在极点退化。
 地表半径和障碍占用都烘成等距圆柱（经纬）展开的格网：地形逐三角形做重心插值
 （按包围盒填最大值会让地面变成台阶、车一路弹跳），障碍只取物体贴地那 30%
 的横截面（树冠比树干宽十几倍，拿整体包围盒会把整条街堵死）。
 路网靠材质名分车道 / 人行道：电动车、车流、出生点只认车道，
 邮箱和停靠车辆可以上人行道，草坪和山地一概不算路。

【尺度：game.js 顶上的 S】
 星球城市是按「巨人尺度」建的：路灯 28.8 米高、马路 16 米宽、楼 30 米高。
 照真人 1.72 米把角色放进去，人和车就成了地上的小蚂蚁，所以整套长度和
 速度都乘 S（现在是 3），角速度（转向速率、转身跟随）保持不变——
 这样转弯半径 v/ω 和跳跃高度 v²/2g 正好也跟着放大 S 倍，手感和放大前一致。
 跟着乘 S 的还有：镜头距离与高度、描边宽度（描边粗细 ∝ 世界宽度/距离，
 镜头远了就得加粗）、阴影范围、太阳距离、云、小地图半径、各种碰撞半径与
 搜索距离。凡是描述城市模型本身的量不参与缩放：FLAT（路缘高度容差）、
 EYE / VIEW_ARC（能看多远）、雾、格网分辨率。
 HUD 上的速度和距离会除回 S 显示，不然会看到一辆 150km/h 的电动车。

【性能】
 three.js 只做视锥剔除、不做遮挡剔除，星球另一面的几千栋楼照样会进 draw call。
 这里按几何关系手工算地平线：眼高 e 时地平线在 acos(R/(R+e)) 角距处，
 高 H 的物体自己还能再露出 acos(R/(R+H))，超出就整个跳过，每帧只要一个点积。
 所以「楼多久才出现」是高度决定的：眼高 15 米时地面地平线只有 134 米，
 30 米高的楼能在 322 米外看到，100 米的塔能在 478 米外看到。
 VIEW_ARC 是这之上再加的一刀硬上限（手机 450 / 桌面 580），它必须大于雾的远端，
 否则楼会在雾外面被硬切掉、出现「凭空冒出来」。
 描边壳只在 ARC_LINE=150 米内画：壳厚 0.045 单位，100 米外不到半个像素，
 关掉它省下的提交正好抵掉看得更远多出来的楼（手机档 339 次提交 / 可见 254 个物体）。
 3007 个 mesh 里只有 201 份不同网格（FBX 把每棵树都导成独立 mesh），
 启动时按顶点指纹去重共用几何体，显存从 216MB 降到 16MB。
 不做合批：球面上大部分物体本来就在地平线外，逐物体剔除比合批更划算。

【街景】
 路上有自动行驶的车流（会避让、路口转向），路边有停靠车辆；
 星球本身自带 1141 棵树和 945 丛草，所以不再额外种树。
 撞到行驶车辆会被弹开并减速。取信时信封飞入 HUD，送达时金币飘字。
